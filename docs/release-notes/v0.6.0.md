This release makes pqsign stricter and clearer about broken input, and ships licence notices with every download. No file format changes: keys and signatures from every earlier release work as before, and so do the commands' options and exit codes.

## Behaviour changes

- **`inspect` reports corrupt secret keys.** It used to read only the header of a secret key file, so a truncated or padded file showed up as a valid key while `sign` rejected it. It now runs the same checks as `sign` does before asking for a password, including the file's length. A damaged file that still has the right length is only caught when the key is used, because the contents are encrypted.
- **Malformed input always reports as `invalid format: …`.** Before, depending on the file, it could say `base64 error: …` (a public key that isn't valid base64) or `crypto error: …` (public key bytes the algorithms reject, or a format v2 secret key whose keys don't match its key ID). The exit status is still 2. The error for a format v1 secret key whose key ID doesn't match stays as it was.
- **A file of the wrong type names both types**, for example `expected a secret key file, got a signature file`. Before, a public key read printed an internal type name, `got: SecretKey`.
- **`sign` rejects a directory before asking for the password.** It used to ask for the password, derive the key, and only then fail. With a wrong password it even reported `wrong password`.
- **A failed password read says where it read from.** A read error on standard input printed a bare `I/O error: …`. It now says `standard input: …`, and a failed read of a password file names the file.

## New in the downloads

- **Licence notices.** Every archive now contains `LICENSE` and `THIRD-PARTY-NOTICES.txt` next to the binary: the licence texts and copyright notices of the crates compiled into it. Their licences (BSD-3-Clause, MIT, Apache-2.0) ask for these notices to ship with binaries.

## Under the hood

- **More release checks:**
  - The release workflow runs the library, fixture and Wycheproof tests with the release profile on Linux x86_64, macOS arm64 and Windows, and runs each of those built binaries end to end.
  - It checks publishing before the GitHub release exists.
  - It verifies the published downloads before the crate goes to crates.io.
- **A licence check in CI.** `cargo deny` allows only permissive licences, and only crates from crates.io.
- **A faster test suite**, about 9 s instead of 16 s.
- **Library API changes** (the library is not a stable interface):
  - Removed: `Error::Io`, `Error::Base64`, `KeyId::random`, `format::escape_comment_field`, and the `format` re-exports of `FileHeader` and `FileType`.
  - Now private: `domain::signature`. `SUITE_ED25519_MLDSA65` is now exported from `domain`.
  - Added: `PublicKey::to_parts` and `SignatureFormat::number`.
  - Changed: `format::encode_public_key` returns a `String` instead of a `Result`, and `commands::inspect::run` takes a `&Path`.
